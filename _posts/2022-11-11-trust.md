## Reflections on Trusting Trust & AI
In the previous posts we highlighted the importance of Mechanistic Interpretability of studying the brain. Here we highlight the importance from an information-security standpoint.

### Background
Reflection on trusting trust is a seminal information-security paper written in 1984 by Ken Thombson [1].
In a three pages long article Thompson demonstrated a technique of injecting an undetectable backdoor deep into the compiler making the entire computer systems untrustworthy. This paper exposed the term and popularized concept of A Trojan Horse. He summarizes the moral lesson of his attack with the following words:
> You can't trust code that you did not totally create yourself

The attack is very simpler and comprised of three steps:
1. Inserting a backdoor by modifying the source code of a software. The modified software could for example be the login-screen for the operating system, allowing the attacker to login successfully without knowing the admin's password.

2. An attacker could modify a compiler, to inspect the source code inserted. If the source code is of the operating system login, the compiler can modify the code itself injection the backdoor.

3. Lastly, an attacker can modify the compilter code, inspect the source code inserted. If the source code is of the compilter itself! the compiler will inject the backdoor from step two, propogating itself to all compilers build from that one.

Since all the components of your system were once compiled, and the original compiler is long gone, the backdoor will be undetectable in any source code. It will however, lie there in machine-instructions and anyone having the tools and skills to reverse-engineer software will be able to locate the backdoor and eliminate it from the system.(*Note on that later*)

### AI risks
This paper suggests that we cannot trust code we didn't created ourself. When we optimize neural-networks we face the same problem. The weights of the network implement some functionallity which we have very little control over. Since neural-nets are universal approximators we could modify the weights to implement any function that we want, including a backdoor. The following paper was written accordingly by Or Zamir one of the members of Mentaleap [2].

### Summary
This suggests that as long as we are unable to fully reverse-engineer and steer the functionallity of neural networks, an inherent risk will exist. Even if we manage to solve the alignment problem and make AI human-friendly, attackers that gains access to the nets will be able to modify them and implant their backdoors.

*The backdoored compiler could inject itself to a disassembler, or any of the tools that are used by the defender. An analogous attack that will protect the true weights of the system from a defender is impratical for the foreseeable future for any advanced general-purpose AI system (AGI), however should be taken into account!*
