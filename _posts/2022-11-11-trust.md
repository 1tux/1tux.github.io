The previous posts illustrated the importance of Mechanistic Interpretability for studying the brain. Now we highlight the importance from an information security perspective.

### Background
In 1984, Ken Thombson authored a seminal paper on information security, Reflection on trusting trust. [1]. In a three-page article Thompson demonstrated a technique of injecting an undetectable backdoor deep into the compiler making the entire computer system untrustworthy. This paper popularized the idea of digital Trojan horses. He summarized the moral lesson of his attack in the following words:
> You can't trust code that you did not totally create yourself

This attack can be broken down into three simple steps:
1. It is possible to insert a backdoor into software by modifying the source code. For example, one could modify the code implementing the login screen for an operating system. Once the compiled OS is deployed, an attacker will be able to bypass the login screen and gain admin access.

2. An attacker could modify a compiler to inspect the source code inserted. If the source code is part of the system login, the compiler could inject the backdoor from step one. [Now the malicious code doesn't appear on the operating system even though it is the system that is attacked. Anybody with access to the compiler's sourcecode however will be able to find and detect the backdoor.]

3. Moreover, an attacker could modify a compiler to inspect the source code inserted. If the source is a compiler, the malicious compiler will inject the backdoor from step two into it. This adds a self-replication mechanism to the backdoor that will propagate itself to all compilers and software based on that one.

Since all the components of your system were once compiled, and the original compiler is long forgotten, the backdoor will be undetectable in any source code. It will however, lie there in machine instructions and anyone having the tools and skills to reverse-engineer software will be able to locate the backdoor and eliminate it from the system. (_Note on that later_)

### AI risk
This paper suggests that we cannot trust code we didn't created ourself. When we optimize neural-networks we face the same problem. The weights of the network implement some functionallity which we have very little control over. Since neural-nets are universal approximators we could modify the weights to implement any function that we want, including a backdoor. The following paper was written accordingly by Or Zamir one of the members of Mentaleap [2].

### Summary
This suggests that as long as we are unable to fully reverse-engineer and steer the functionallity of neural networks, an inherent risk will exist. Even if we manage to solve the alignment problem and make AI human-friendly, attackers that gains access to the nets will be able to modify them and implant their backdoors.

*The backdoored compiler could inject itself to a disassembler, or any of the tools that are used by the defender. An analogous attack that will protect the true weights of the system from a defender is impratical for the foreseeable future for any advanced general-purpose AI system (AGI), however should be taken into account!*
